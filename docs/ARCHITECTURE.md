# Архитектура LLM Dict

## Компоненты

### Recorder firmware

`firmware/llm_dict_recorder` работает на Seeed Studio XIAO nRF52840 Sense Plus. Он захватывает mono PCM 16 кГц / 16 бит со встроенного PDM-микрофона, сохраняет один WAV во встроенную 2 МБ QSPI flash и отдаёт завершённый файл по USB CDC или BLE.

Для защиты от ошибочного стирания прошивка проверяет JEDEC ID и ожидаемый размер flash. Запись считается доступной только после финализации WAV-заголовка.

### BLE transport

Устройство рекламируется как `LLM Dict Recorder`, использует Nordic UART Service и собственные бинарные команды `LDI1`, `LDG1`, `LDC1`. Передача завершается полным CRC32 WAV-файла. Точная структура фреймов находится в [BLE_PROTOCOL.md](BLE_PROTOCOL.md).

### iOS application

Нативное приложение использует SwiftUI, SwiftData, AVFoundation, CoreBluetooth и Keychain:

- `App/` — жизненный цикл и orchestration;
- `Features/` — запись, история, настройки, руководство и BLE-компаньон;
- `Support/` — модели, credentials, сетевые и аудиосервисы;
- `Design/` — Liquid Glass с fallback для iOS 17–25.

Проект генерируется из `apps/ios/project.yml` через XcodeGen. Сгенерированный `.xcodeproj` также хранится в репозитории, поэтому для обычной установки XcodeGen не нужен.

## Поток данных

1. Пользователь записывает аудио на устройстве или прямо на iPhone.
2. При BLE-синхронизации iOS проверяет identity устройства, объявленный размер, WAV header и CRC32.
3. Аудиофайл и метаданные сохраняются локально; история живёт в SwiftData.
4. Явное действие **Распознать** отправляет аудио выбранному STT-провайдеру.
5. Сырой текст сохраняется отдельно от результата обработки.
6. Явное действие **Оформить** отправляет текст и выбранный шаблон LLM-провайдеру.
7. Пользователь копирует, экспортирует или повторно обрабатывает результат.

## Границы доверия

| Граница | Что покидает устройство | Контроль пользователя |
| --- | --- | --- |
| Recorder → iPhone | WAV по BLE | Локальное сопряжение, проверка identity и CRC32 |
| iPhone → STT | Аудиофайл | Провайдер выбирается в настройках; отправка только по явному действию |
| iPhone → LLM | Текст и шаблон | Отдельное действие «Оформить» |
| iPhone storage | WAV, transcript, настройки | App sandbox, SwiftData и Keychain |

## Текущие технические ограничения

- BLE v1 поддерживает resume на уровне firmware, но iOS MVP начинает синхронизацию с нулевого offset.
- Flash рассчитана на один WAV до 2 МБ; прошивка ограничивает полезную запись 60 секундами.
- Реальный live transcription требует отдельного token broker и короткоживущих client secrets; экспериментальный код не включён в основной пользовательский поток.
